# Mini-CRM для учёта сделок (Windows и macOS)

Это локальная CRM: таблица сделок + карточка клиента с лентой событий + документы клиентов и событий + авто «последний контакт» + фильтры/поиск/многоуровневая сортировка + отчёт + BI‑аналитика + экран «Активность» + экспорт/бэкап.

## Установка без Git и централизованные обновления

В [публичном репозитории CRM-TechPres](https://github.com/rshamrin/CRM-TechPres) нажмите **Code → Download ZIP**. Аккаунт GitHub, Git и ключ для скачивания не нужны. Понадобятся Python 3.11+ и доступ к GitHub для проверки обновлений.

1. Распакуйте ZIP в постоянную отдельную папку на компьютере. Не запускайте файлы прямо из ZIP.
2. Если раньше использовали эту CRM, закройте её, сохраните резервную копию старой папки и перенесите **свои** `data/` и при желании `backups/` в новую папку. Не переносите `.venv/` и не подменяйте базу другого сотрудника.
3. На Windows откройте `run.bat`, на macOS — `run.command` (при необходимости выполните `chmod +x run.command`). Затем откройте http://127.0.0.1:8000.
4. Для следующих запусков открывайте тот же файл в той же папке. Повторно скачивать ZIP не требуется.

Перед запуском `update.py` проверяет последний коммит ветки `main`, скачивает новые исходники и обновляет приложение. Если сеть недоступна, запускается установленная версия (если зависимости уже установлены). Для уже открытой CRM изменения применятся при следующем запуске. При обновлении база `data/app.db` копируется в `backups/pre_update_*.db`; рабочие `data/` и `backups/` не заменяются. Автоматическая копия содержит только базу: для сохранения вложений используйте кнопку «Бэкап» в CRM.

Этот репозиторий содержит только код. База, документы и резервные копии остаются у каждого сотрудника локально. **Не загружайте исходный `Архив.zip` в GitHub:** в нём есть рабочая база SQLite и её копии. Не копируйте новые файлы поверх рабочей папки вручную.

Если владелец проекта работает с Git, можно также использовать `git clone`; в таком каталоге обновление выполняется через Git. Локальные правки исходников в Git-клоне блокируют автоматическое обновление. В установке из ZIP файлы приложения обновляются версией из GitHub, поэтому свои правки в них не сохраняйте.

### Как выпускать обновление

Владелец изменяет исходники и публикует новый коммит в `main` на GitHub. Например, из своей копии с Git:

```bash
git add app requirements.txt update.py README.md .gitignore
git commit -m "Обновление CRM"
git push origin main
```

При следующем запуске коллеги получат новую версию. Файлы запуска `run.bat` и `run.command` берутся из первоначального ZIP; если их потребуется изменить, попросите коллег скачать новую папку и перенести свои `data/` и `backups/`. GitHub распространяет версии кода, а не общую базу клиентов. Для совместного редактирования одних и тех же клиентов понадобится серверное приложение с общей БД и управлением доступом.

## Документы и папки
- В карточке клиента раздел «Документы клиента» показывает единый список всех файлов: прикреплённых прямо к клиенту и добавленных к его событиям.
- Кнопка «+ Добавить» в этом разделе прикрепляет файлы или папку непосредственно к клиенту.
- Кнопка со скрепкой у события открывает его собственные вложения.
- При выборе папки загружаются все содержащиеся в ней файлы и сохраняются относительные пути подпапок. Пустые папки браузер не передаёт.
- Ограничения одной загрузки: до 500 файлов, до 100 МБ на один файл и до 500 МБ суммарно.

## BI‑аналитика
- Страница: http://127.0.0.1:8000/analytics
- Поиск событий по точному комментарию или фразе внутри комментария
- Фильтры по датам, типу события и sales
- Детализация по дням, неделям, месяцам, кварталам или годам
- Динамика, сравнение с предыдущим равным периодом, разрезы по sales и типам событий
- Расшифровка до отдельных событий и выгрузка результата в CSV

## Сортировка отчёта
Отчёт использует многоуровневую сортировку, выбранную на главной странице, и применяет её внутри разделов отчёта.

## Запуск (вариант 1 — одной кнопкой)
1) Скачай ZIP из репозитория и распакуй в постоянную папку
2) На MacOS Открой терминал и введи xattr -d com.apple.quarantine /путь/к/run.command
3) На macOS открой `run.command`, на Windows — `run.bat`
4) Открой в браузере: http://127.0.0.1:8000

Если macOS спросит про безопасность — разреши запуск (System Settings → Privacy & Security).

На Windows окно `run.bat` остаётся открытым после ошибки или завершения CRM, чтобы был виден текст диагностики. Если двойной щелчок не открывает окно, запусти `run.bat` из обычной командной строки и сохрани вывод ошибки.

## Запуск (вариант 2 — вручную)
```bash
cd /путь/к/папке/CRM
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

## Где лежат данные
- База SQLite: `data/app.db`
- Загруженные документы: `data/attachments/`
- Бэкапы: `backups/`

Кнопка «Бэкап» создаёт архив `backups/crm_ГГГГММДД_ЧЧММСС.zip`, в который входят база и все вложения.

## Экспорт
- Клиенты: http://127.0.0.1:8000/export/clients.csv
- События: http://127.0.0.1:8000/export/events.csv
