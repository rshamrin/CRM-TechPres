# Mini-CRM для учёта сделок (Windows и macOS)

Это локальная CRM: таблица сделок + карточка клиента с лентой событий + документы клиентов и событий + авто «последний контакт» + фильтры/поиск/многоуровневая сортировка + отчёт + BI‑аналитика + экран «Активность» + экспорт/бэкап.

## Централизованные обновления через GitHub

Этот каталог содержит только код. `data/` (база и вложения), `backups/` и `.venv/` создаются локально, исключены из Git и остаются у каждого сотрудника. **Не загружайте исходный `Архив.zip` в GitHub:** в нём есть рабочая база SQLite и несколько её копий.

На каждом запуске `run.bat` или `run.command` файл `update.py` проверяет отслеживаемую ветку Git и, если есть новая версия, сохраняет копию локальной базы в `backups/pre_update_*.db` и обновляет код. После этого запускается CRM. Если Git или сеть недоступны, запускается установленная версия (при наличии необходимых зависимостей). При локальных правках исходников обновление пропускается во избежание конфликтов. Уже открытая CRM обновится после следующего запуска.

### Первый раз: владелец проекта

1. Создайте **приватный** пустой репозиторий на GitHub; при создании не добавляйте README и `.gitignore`.
2. Распакуйте **этот подготовленный архив** в отдельную папку и откройте терминал в этой папке.
3. Перед отправкой проверьте список файлов: в нём не должно быть `data/`, `backups/`, `.db`, клиентских документов и секретов.
4. Выполните команды (замените `OWNER` и `REPO` на свои значения):

```bash
git init -b main
git add .
git status --short
git commit -m "Initial CRM source"
git remote add origin https://github.com/OWNER/REPO.git
git push -u origin main
```

**Важно:** GitHub должен быть доступен с компьютеров сотрудников. Для приватного репозитория у каждого нужен свой доступ и работающая аутентификация командной строки Git; токен в исходниках и запускателях не нужен. Добавьте коллег в доступ к репозиторию. Для разграничения прав на чтение и запись удобнее репозиторий организации: у приватного репозитория личной учётной записи GitHub приглашённые сотрудники получают право записи.

### Каждый сотрудник: установка и перенос данных

1. Установите Python 3.11+ и Git для своей ОС, настройте доступ к приватному репозиторию.
2. Склонируйте репозиторий в свою отдельную папку: `git clone https://github.com/OWNER/REPO.git`.
3. Если CRM уже использовалась, закройте её, сделайте резервную копию своей старой папки, перенесите **только собственные** `data/` и при желании `backups/` в новый клон. Не переносите `.venv/` и не заменяйте чужой файл `data/app.db`.
4. Запустите `run.bat` (Windows) либо `run.command` (macOS). В следующий раз запускайте тот же файл из клонированной папки.

Кнопка «Бэкап» в CRM создаёт полный архив базы и вложений; автоматический файл `pre_update_*.db` перед обновлением кода содержит только базу. Он не заменяет резервную копию вложений.

### Как выпускать обновление

Из папки владельца проекта внесите изменения в код, проверьте их и выполните:

```bash
git add app requirements.txt run.bat run.command update.py README.md .gitignore
git commit -m "Describe CRM update"
git push origin main
```

После следующего запуска у сотрудников код обновится. GitHub здесь распространяет **версии приложения**, а не общую базу клиентов. Для совместного редактирования одних и тех же клиентов потребуется серверное приложение с общей БД и управлением доступом.

## Документы и папки
- В карточке клиента раздел «Документы клиента» показывает единый список всех файлов: прикреплённых прямо к клиенту и добавленных к его событиям.
- Кнопка «+ Добавить» в этом разделе прикрепляет файлы или папку непосредственно к клиенту.
- Кнопка со скрепкой у события открывает его собственные вложения.
- При выборе папки загружаются все содержащиеся в ней файлы и сохраняются относительные пути подпапок. Пустые папки браузер не передаёт.
- Ограничения одной загрузки: до 500 файлов, до 100 МБ на один файл и до 500 МБ суммарно.

## BI‑аналитика
- Страница: http://127.0.0.1:8000/analytics
- Поиск событий по точному комментарию или фразе внутри комментария
- Фильтры по датам, типу события и sales
- Детализация по дням, неделям, месяцам, кварталам или годам
- Динамика, сравнение с предыдущим равным периодом, разрезы по sales и типам событий
- Расшифровка до отдельных событий и выгрузка результата в CSV

## Сортировка отчёта
Отчёт использует многоуровневую сортировку, выбранную на главной странице, и применяет её внутри разделов отчёта.

## Запуск (вариант 1 — одной кнопкой)
1) Склонируй проект из GitHub или распакуй папку проекта (при запуске из архива автообновления не подключены)
2) На macOS открой `run.command`, на Windows — `run.bat`
3) Открой в браузере: http://127.0.0.1:8000

Если macOS спросит про безопасность — разреши запуск (System Settings → Privacy & Security).

На Windows окно `run.bat` остаётся открытым после ошибки или завершения CRM, чтобы был виден текст диагностики. Если двойной щелчок не открывает окно, запусти `run.bat` из обычной командной строки и сохрани вывод ошибки.

## Запуск (вариант 2 — вручную)
```bash
cd /путь/к/папке/CRM
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

## Где лежат данные
- База SQLite: `data/app.db`
- Загруженные документы: `data/attachments/`
- Бэкапы: `backups/`

Кнопка «Бэкап» создаёт архив `backups/crm_ГГГГММДД_ЧЧММСС.zip`, в который входят база и все вложения.

## Экспорт
- Клиенты: http://127.0.0.1:8000/export/clients.csv
- События: http://127.0.0.1:8000/export/events.csv
